二、项目简介

SwarmBox 是一个不可逃逸、可复跑的多智能体测试床，为 AI Agent 的安全与对齐研究而设计。

它最根本的设计选择是：不解释执行智能体的输出，而是把输出当作纯数据来解析。因此文件、网络、进程、import、反射等逃逸手段根本不在语法里——不是"被禁止"，而是"无从调用"。这使"不可逃逸"成为一个结构性事实，而不是一份需要不断维护的禁止清单。

每次提案都要经过三重校验：结构（check_shape）、身份（check_identity）、状态（check_state）；任一不过即被闸门 screen() 拒绝，并写入只追加账本（append-only ledger）。因此"从未发生逃逸"是可审计的历史记录，而非一句需要被相信的承诺。

项目内置公共资源池经济，可观测 5–20 个智能体在共享资源下是协作、合谋还是耗尽资源。复现成本极低：git clone && python eval.py，离线运行 235 条断言，0 失败。

三、要解决的问题

多智能体系统正从实验室走向生产环境。一旦给一群智能体授予工具与共享资源，风险就从"单个模型会不会乱说"升级为"一群智能体会不会合谋、逃逸、耗尽资源"——而这在上线前几乎无法系统性检验。当前存在三个具体缺口：

  • 逃逸风险无法预检：智能体被授予工具权限后，文件 / 网络 / 进程等逃逸路径难以穷举验证。
  • 禁止清单式沙箱易被绕过：靠"不许调用 X"实现的隔离总会有遗漏，且无法证明已穷尽。
  • 群体行为缺乏实验环境：合谋、资源耗尽等现象缺少可复现、可量化的观测平台。

SwarmBox 把这三个问题各自落地为可运行、可断言的代码，而不是停留在方案描述层面。

四、技术方案

世界模型 world.pyclass World 维护公共资源池与系统不变量，违反时抛 InvariantError
闸门 gate.pyscreen() 串联 check_shape() / check_identity() / check_state() 三重校验
账本 ledger.pyclass Ledger 只追加记录全部被拒提案，支持 read_ledger() 回放
攻击语料 probe.py32 条逃逸尝试，用于验证不可逃逸性
保真度 fidelity.pyaggregate() / compare() 支持多规模多轮次消融实验
其余模块agents.py（智能体）、swarm.py（群体调度）、metrics.py（指标）、chain.py（链式实验）

关键实现要点：智能体输出全程作为数据结构处理，从不进入任何执行或求值路径；所有阈值与规则属于世界配置，不由提案内容决定，因此智能体无法用输出影响自身约束。

五、创新点

  • 不解释执行，只作数据解析——逃逸手段不在语法里，攻击面不存在，而非被封堵。
  • 三重校验层层收窄——结构、身份、状态三层各自独立，任一不过即拒绝。
  • 可审计而非需信任——只追加账本使安全性成为可核对的历史记录。
  • 群体行为可量化——合谋相关系数、collapse_rate、gini 等指标把"群体是否合谋"变成可计算的量。
  • 零依赖零网络——纯 Python 标准库，任何环境一次命令即可完整复现。

八、后续发展计划

  • 扩展逃逸语料库：从 32 条扩展到 100+ 条，覆盖同形字、归一化绕过、结构膨胀等新型手法。
  • 增加资源策略维度：引入配额、优先级、惩罚机制，观察更丰富的群体动力学。
  • 可视化回放工具：把只追加账本渲染成时间轴，直观呈现"谁在何时试图逃逸、命中哪条规则"。
  • 对齐实验基线：发布标准对照实验配置，供其他研究者做可比较的合谋 / 资源耗尽研究。
  • 文档与教程：补充中文教程，降低 AI 安全研究者与本专科学生的上手门槛。
